# Tooling: CLI, evaluation, tests, benchmarks, CI

## CLI (`crates/cli`, binary `pattern-guard`)

A thin binary over the engine. Arguments are parsed by hand (no clap), in `args.rs`.

| Command | Module | What it does |
|---|---|---|
| `pattern-guard replay [--config F] [--model M] [--format auto\|jsonl\|combined] [--top N] LOG` | `replay.rs` | Streams an access log (`-` for stdin) through a `Guard` using **event time**, and reports decisions per bucket and the top actors. With labelled JSONL it also reports false positives and detection per scenario |
| `pattern-guard train [--config F] [--epochs N] [--l2 X] [--lr X] [--no-balance] [--no-augment] [--augment-weight W] -o OUT LOG` | `train.rs` | Computes features with the same `FeatureEngine` as production, balances classes and scenarios, adds mimicry copies, trains, writes model TOML |
| `pattern-guard --config F [--repeat N] [--] CMD [ARGS…]` | `wrap.rs` | Runs a command under the guard, one event per run (rate-limit cron jobs or scripts) |

Log formats (`engine/src/logs.rs`): nginx/Apache combined, and JSONL with `ts`, `path` (alias `target` / `url`
/ `uri`), and optionally `actor` / `ip`, `method`, `status`, `ua`, `fp` (alias `ja4` / `ja3`), `weight`, `label`
(`1` = abusive) and `scenario`. Training gives each class half the total weight, and within a class, each
scenario an equal share (`--no-balance` turns this off).

```
access.log ──► replay ──► report (decisions, top actors, FP / detection with labels)
labelled.jsonl ──► train ──► model.toml ──► guard.toml: model = "model.toml"
                                        └─► replay --model model.toml   (check before deploying)
```

## Evaluation (`tools/eval`, unpublished crate `pattern-guard-eval`)

| Binary | Measures | Input |
|---|---|---|
| `realworld_eval [--model M] [--seed N]` | Behavioural ML: one simulated hour of one site, legitimate background traffic plus staggered attacks, including `[unseen]` variants and a flash-sale surge never used in training. It compares the 0.2-style rules with the adaptive engine | generated by `src/sim.rs` |
| `gen_traffic [--seed N] [--hours H] [--unseen]` | Writes labelled synthetic JSONL for `pattern-guard train` / `replay` | — |
| `waf_eval --attack F … --benign F …` | WAF detection and false positives per file (one value per line) | external payload lists (PayloadsAllTheThings, SecLists, fuzzdb) and benign lists |
| `crs_eval FILE [--pl N]` | WAF against the OWASP CRS regression tests (attack categories 930–944). `DUMP=1` prints every score; `SHOW_NEG=1` lists blocked negative tests | `crs_tests.jsonl` from `scripts/extract_crs_tests.py` |

```
coreruleset checkout ──► python3 -I scripts/extract_crs_tests.py ──► crs_tests.jsonl ──► crs_eval
                         (YAML parsed as data only, no code runs; needs PyYAML)
```

**Reproducible data.** `scripts/fetch_eval_data.sh` downloads every dataset at a pinned commit
into the git-ignored `tools/eval/data/` (nothing is redistributed), verifies each file against
`tools/eval/datasets.sha256` (`--update` rewrites it after a pin changes), and builds:

| Set | Source | Use |
|---|---|---|
| `dev/<class>.txt` | PayloadsAllTheThings payload lists (SQLi, XSS, command injection, traversal, LFI, NoSQL, SSTI) | development: fix categories here |
| `holdout/<class>.txt` | SecLists and fuzzdb (SQLi, XSS, LFI, commix command injection) | **measure only, never tune** |
| `benign/*.txt` | SecLists names and English words, SecLists user agents, code lines from the Rust book | false positives |
| `crs_tests.jsonl` | OWASP CRS regression tests at the commit of the vendored CRS lists | development data since WAF 2.0 |

Development lines that also appear in a hold-out list are removed (PayloadsAllTheThings copies
some SecLists / fuzzdb lists), so the hold-out stays a hold-out. `scripts/eval_waf.sh` runs all of
it and prints one summary; run it from an older worktree with `DATA=…` to compare commits on
the same data.

**Data hygiene.** Hold-out lists are never used for tuning. A result measured on development
data must say so.

## Tests

| Level | Where | Notes |
|---|---|---|
| Unit | `#[cfg(test)] mod tests` in nearly every module | Time-dependent code takes `now` (`check_at`, `record_block_at`, event-time `Guard`) so tests never sleep |
| WAF corpus | `crates/waf/tests/corpus.rs` | Real-world attacks and tricky benign values; the benign side must stay at 0 blocks |
| Engine behaviour | `crates/engine/tests/adaptive.rs` | Scenarios against the built-in model (browsers stay allowed, abusers are caught) |
| CLI | `crates/cli/tests/cli_integration.rs` | Spawns the real `pattern-guard` binary |
| Gateway end-to-end | `crates/gateway/tests/e2e.rs` | A real upstream, a mock CrowdSec LAPI and the gateway over TCP on `127.0.0.1:0`; 18 tests, one per feature area (WAF, multipart, operations and logins, exclusions, trusted proxies, proof-of-work round trip, CrowdSec, Suricata, detect mode, admin, rules, rate limits, bans and traps, protocol, headers, data leaks, geo) |
| Doc tests | `engine/src/lib.rs` | `no_run` usage example |

## Benchmarks and examples

| Command | Purpose |
|---|---|
| `cargo bench -p pattern-guard-waf --bench inspect_bench` | WAF cost per request; catches the DFA-cache fallback (≈ 60× slowdown) |
| `cargo bench -p pattern-guard --bench check_bench` | Engine cost per `assess` |
| `cargo run --release -p pattern-guard-gateway --example loadtest -- [concurrency] [seconds]` | Gateway against the bare upstream in one process. Client, gateway and upstream share the CPU, so the result is a lower bound |
| `cargo run -p pattern-guard --example burst_demo` / `repetition_demo` | Threshold-rule demos using `config/demo/*.toml` |

## CI (`.github/workflows/`)

| Workflow / job | When | What |
|---|---|---|
| `rust.yml` · `check` | every push and pull request to `main` | Rust **1.85** (the MSRV, also the Docker build image): `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test --workspace`, `cargo bench --workspace --no-run` |
| `rust.yml` · `stable` | same | newest stable Rust: `cargo test --workspace`, `cargo doc --workspace --no-deps` with `RUSTDOCFLAGS=-D warnings` |
| `rust.yml` · `deny` | same | `cargo-deny` with `deny.toml`: permissive licences only, every RustSec advisory fails, crates.io only |
| `fuzz.yml` | nightly (300 s per target), pull requests touching parsers (60 s), by hand | `cargo fuzz` on nightly for each target in `fuzz/`, starting from the cached corpus (saved again except on pull requests); a crashing input is uploaded as an artefact |
| `fuzz-long.yml` | weekly (Friday 19:00 UTC), by hand | the 24 h run: the five targets in parallel for 4.8 h each (job timeout 330 min, under GitHub's 6 h cap), then `cargo fuzz cmin` and the corpus is cached for the next run |

Not in CI yet: evaluation gates (`waf_eval`, `crs_eval`, `realworld_eval` must not regress).
They need the evaluation datasets to be fetchable reproducibly first; see [target.md](target.md).

## Fuzzing (`fuzz/`)

A separate cargo workspace (cargo-fuzz needs nightly). Targets:

| Target | Exercises |
|---|---|
| `waf_inspect` | whole-request inspection: target, header values, body under six content types |
| `waf_multipart` | the multipart parser and upload checks |
| `waf_value` | one value through the decoder, every variant and every analyser, at eight locations |
| `engine_log_line` | access-log parsing (combined and JSONL) |
| `config` | gateway config + compiling rules, rate limits and operations; engine config; model files |

```bash
cargo install cargo-fuzz          # needs a nightly toolchain and a C++ compiler
cargo +nightly fuzz run waf_inspect fuzz/corpus/waf_inspect fuzz/seeds/waf_inspect
```

cargo-fuzz builds for the target it was itself compiled for. A prebuilt binary (CI's
`taiki-e/install-action`, `cargo binstall`) is a musl build, and nightly has no musl
standard library, so pass `--target x86_64-unknown-linux-gnu` (CI does).

Seed inputs live in `fuzz/seeds/<target>/` (committed). The growing corpus and crash
artefacts (`fuzz/corpus`, `fuzz/artifacts`) are git-ignored; CI keeps the corpus in the
Actions cache (`fuzz-corpus-<target>-…`), shared by the nightly and the weekly run.
